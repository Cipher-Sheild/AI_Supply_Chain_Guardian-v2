# ML teammate handoff — Checkpoint 1

No trained model, XGBoost or SHAP is implemented. Contract 1.0 is documented in `CONTRACT_V1.md`. Independently built services share generated contract/capability copies; drift check: `python3 scripts/sync_contracts.py --check`.

`services/trust_engine/app/scorers.py` defines `Scorer.score(state, total_risk) -> finite float in [0,100]`. `WeightedSumScorer` is the default: clamp(100 − sum(severity weight × confidence)). `fuse(state, scorer=...)` is the injection seam. Hard overrides run first and return zero/Reject without invoking the scorer. Coverage, status, unresolved, license-review and severity floors remain outside the model and authoritative. A model cannot override them. Prefer monotonic responses as risk, severity, confidence, missing checks or uncertainty increase. Calibrate on independently labeled artifacts; platform recommendations are policy outputs, not ground-truth labels.

`FEATURE_LOG_PATH` controls append-only JSONL observations (default `/tmp/guardian-features.jsonl`, empty disables). Each event has feature_version, contract_version, request_id, timestamp, phase (`initial` or `callback`), files and outcome. Each file has index, artifact_type, routing_source, routing_coverage, and seven agent keys. Unselected or missing results are null. Attempted failures carry ran/status/timing with unavailable measurements null. Completed results carry coverage, unresolved, decision_floor, severity_counts, max_confidence, hard_blocks, numerical agent_specific_scores (including clean CipherGuard package_scores), elapsed_ms. These are observed values before feature aggregation; clean successful zero counts are distinct from null measurements. Scores are not comparable across agents without calibration.

For privacy the log excludes content, paths, package names, snippets, reasons, secrets, judge prompts and unrestricted evidence. Raw unrestricted detector responses remain in scan state/API evidence; they are not duplicated into the training log. New numeric features require explicit whitelist changes and schema-version review. Files are created with mode 0600. Mount a protected persistent path in production; default /tmp is temporary. Log write failures are reported but do not alter the security decision. Retention, rotation and cross-process durability are Checkpoint 2 operational work.

Join callback observations by request_id and file_index. Initial provisional outputs must not masquerade as final observations or independent labeled samples. Do not fill missing checks with zero. Unknown licenses/expressions, missing tools and registry outages remain uncertainty. SPDX expression trees preserve AND/OR/WITH/nesting; unsupported exceptions hold Review. Validate on direct service serialization and Trust Engine round trips, plus full Compose scans when the environment allows them. See STATUS.md for remaining audit work and verification limits.

## Checkpoint 2 integration notes
The scorer file, fuse() seam and feature schema remain unchanged. Public ScanResponse adds `per_file` (not a detector-contract change). Scan persistence is PostgreSQL in Compose; callback application/overdue finalization are atomic. Feature JSONL is retained on a named volume. `scripts/run_labeled_corpus.py` records independently supplied labels and waits for final scans. Batch requests can emit multiple callback rows; choose a row with no selected agent still pending, rather than assuming any callback row is final or relying on append timestamps. Timeout finalization emits the existing callback phase with error/unresolved values. Failure to append the feature log is still a logged observation failure, so verify join completeness before training. The license agent now imposes Review for ordinary conflicts; only explicit organization denylists supply a license rejection override. Default denylists are empty; Go stays partial. No trained model/SHAP was added.

Per-file outcomes are stored with scan snapshots and updated when callbacks resolve; reading history does not invoke the current scorer again. This is an internal snapshot addition, not a feature-schema change.
